= ロードバランシングの簡易構成

== はじめに

多くのシステムでは、仮想マシンのロードバランシングには通常、複数のツールと構成が必要です。
例えば、2 台の仮想マシンに対して内部および外部のロードバランシングを行うには、以下の作業が必要になることがあります。

* [ ] 内部ロードバランサーの作成
* [ ] インターネット向けエンドポイントの作成と内部ロードバランサーへのルーティング
* [ ] 内部ロードバランサー用のプライベート DNS レコードの作成
* [ ] 外部アクセス用パブリックエンドポイントのパブリック DNS レコードの作成
* [ ] ロードバランサーへの仮想マシンの登録
* [ ] リスニング/フォワーディングポートまたはポート変換の構成
* [ ] ヘルスチェックエンドポイントとテストの構成
* [ ] ヘルスチェックのタイムアウトとインターバルの構成

OpenShift はネットワーキングとロードバランシングを大幅に簡素化します。
このモジュールでは、OpenShift を離れることなく、これらすべてを実現します。

[[setupservice]]
== Service による内部ロードバランシングの設定

Service は OpenShift における内部ロードバランサーです。
Service は Label Selector によってリソースを識別し、トラフィックをルーティングします。
Label は仮想マシンを含むあらゆる OpenShift リソースに適用でき、リソースの識別とグループ化に使用されます。
ここでは、Service を作成し、仮想マシンに付与された Label を使ってロードバランシング対象の仮想マシンを特定します。

. 左側のバーで *Virtualization -> VirtualMachines* をクリックし、上部のバーで *Project: `windowsmesh-{user}`* を選択します。
. Service がロードバランシング対象を特定するための Label を確認するには、*`winweb01`* 仮想マシンをクリックします。
*YAML タブ* をクリックし、*「app: winmesh」を検索* します。
通常 186 行目付近にあります。
これは両方の仮想マシンに割り当てられた任意の Label です。
+
.仮想マシンインスタンスの Label を確認
image::module-4-find-vm-app-label.png[Find VM label app=winmesh,link=self, window=blank, width=100%]
+
. コンソール左側で *Networking -> Services* を展開し、右上の *Create Service* をクリックします。
+
.Service の作成を開始
image::module-4-create-service.png[Create Service button,link=self, window=blank, width=100%]
+
. 仮想マシン間でロードバランシングするように Service を変更します。
.. 4 行目で *name:* を `winmesh` に変更します。
.. 8 行目を `app: winmesh` に変更します。
.. 12 行目の *targetPort:* の値を `80` に変更し、左下の *「Create」をクリック* します。
+
.Service 構成の変更
image::module-4-create-service-yaml.png[Create Service YAML,float="none",align="left",link=self, window=blank, width=100%]
+
. *Pods タブ* をクリックし、2 台の `winweb` 仮想マシンがすでに Service オブジェクトに登録されていることを確認します。
これにより、OpenShift クラスター内のアプリケーションは、winmesh Service（ロードバランサー）を通じてこれらの仮想マシンにアクセスできるようになります。
+
.Label Selector で識別された Pod の確認
image::module-4-pods-in-service.png[Pods in Service,float="none",align="left",link=self, window=blank, width=100%]

[[routes]]
== ロードバランシングへの外部アクセスの設定

OpenShift は、Kubernetes の初期に Route の概念を初めて導入しました。
Route を使って、内部 Service（ロードバランサー）を通じて仮想マシンへの外部アクセスを提供します。

. 左側で *Networking -> Routes* をクリックし、*Create Route* をクリックします。
+
.Route の作成を開始
image::module-4-create-route.png[Create Route,float="none",align="left",link=self, window=blank, width=100%]
+
. フォームを使って Route を作成します。
.. *name:* フィールドに `winmesh` と入力します。
.. *Service* の下のドロップダウンボックスをクリックし、先ほど作成した `winmesh` Service を選択します。
.. *Target port* の下のドロップダウンボックスをクリックし、ポート `80` を選択します。
.. *Secure Route* チェックボックスにチェックを入れます。
.. *TLS termination* で `Edge` を選択します。
.. *Insecure traffic* で `Redirect` を選択します。
.. 最後に、左下の *Create* をクリックします。
+
.完成した Route
image::module-4-create-route-form.png[Create Route form,float="none",align="left",link=self, window=blank, width=100%]
image::module-4-create-route-form1.png[Create Route form,float="none",align="left",link=self, window=blank, width=100%]
+
. Route をテストします。
中央右側の *Location* セクションを見つけます。
*リンクをクリックして、ロードバランシングされた仮想マシンを表示します。*
+
.インターネット経由でアクセス可能なアプリケーション
image::module-4-test-route.png[Test Route,float="none",align="left",link=self, window=blank, width=100%]
+
. 新しいブラウザウィンドウが開き、Web アプリケーションにアクセスします。
+
image:module-4-web-application.png[Web Application,float="none",align="left",link=self, window=blank, width=100%]
+
. Route は OpenShift 内部の HAProxy によって実装されています。
デフォルトでは、Cookie に基づくスティッキーセッションが有効です。
必要に応じて、Cookie とスティッキーセッションを無効にするよう Route を更新できます。
+
[,sh,role=execute]
----
oc annotate route winmesh haproxy.router.openshift.io/disable_cookies='true' -n windowsmesh-{user}
----
